# Final answer format (applies to every project)

Every final answer to the user must follow this structure:

0. If the answer is not complex and complicated answer short without structure.
1. **Abstract** — first section. Describe what the problem was, what causes it, and which solution could be applied.
2. **Statements** — a numbered list. Each statement starts with its number, then a short description, then a detailed description (only if needed).
3. **Solution** — propose the solution (only if it makes sense)
4. **Worth knowing** — a closing section with related facts, caveats, or follow-ups worth being aware of.

Every reference to a class, service, method, or file must be a link to the file with a line anchor (e.g. [user.rb:42](app/models/user.rb#L42), or a range [user.rb:42-51](app/models/user.rb#L42-L51)).
